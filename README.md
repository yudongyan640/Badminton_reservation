# 羽毛球场地自动预约程序

> Windows 上的个人羽毛球场地预约辅助工具：Node.js + TypeScript + Playwright，通过独立 Edge 配置完成微信扫码登录、零点自动提交、结果核验与安全暂停。

**当前版本：1.2.25** · 仅面向个人自用，非官方项目。

## About / 项目简介

本程序用于在指定场馆的预约网站上，按预设日期、时段和场地自动完成零点放号预约，并把结果保存在本地控制页。它不依赖云端服务，所有登录资料、任务和运行状态都保存在本机 `data/` 或 `data-b/` 目录中；这些目录已被 `.gitignore` 排除，不会进入仓库。

程序的重点不是“无脑重试”，而是**严格校验 + 可核对 + 出问题就停**：只有能确认“未创建预约”的拒绝结果才允许重试或换场；结果不明时先只读核对本人记录，无法确认就冻结账号后续任务，等待人工核对。

## 主要功能

- **零点自动预约**：按目标日 D−1 北京时间 00:00 的放号规则，提前完成预检、校时和表单演练，在零点触发提交。
- **单账号双实例**：账号1 默认使用 `38321` 端口和 `data/`；账号2 使用 `38322` 端口和 `data-b/`，两个实例的登录、任务、冻结、令牌和日历完全隔离。
- **严格场馆/时段绑定**：只提交用户选择的目标场地和目标时段；识别明确冲突后才在目标范围内换场或换剩余连续时段。
- **部分成功即停止**：取得任何可用时段后立即保留并停止，不补订、不撤销、不自动换场。
- **未知结果安全暂停**：断网、5xx、未知业务响应等不能确认结果时，先核对本人预约；无法确认则持久化暂停，重启后仍保留。
- **零点复查**：预检快照显示目标全占时，零点最多再做一次有界只读复查，避免把“快照过时/网站未开放数据异常”误判为全占。
- **本地控制页**：查看任务、执行预检、演练、启用任务、查看结果和事件；仅监听本机回环地址，并要求本地来源/令牌校验。
- **可测试**：内置单元测试和模拟站点，测试不会创建或取消真实预约。

## 安全与边界

- 正式提交默认串行、单在途，最小间隔 100 毫秒（1.2.20 起），每条任务最多 20 次、15 秒尝试窗口；1.2.21 起，同一批到点且**时段互不重叠**的任务首刀最多 2 条并发，其余任务与后续重试/核对仍严格串行。
- 1.2.22 只增加诊断留痕：每条任务单独保存首刀的场地/时段/触发延迟/响应耗时/结果类型（`firstShot`，重试不覆盖），首轮冲突时记录冲突区间、被掩掉的场地与本地改投目标（`lastConflict` 与 `conflict-local-reselect` 事件）；不改变提交、重试、并发或安全边界。
- 1.2.23 只调整重试顺序：首轮冲突后用缓存完成本地重选、已有新候选时段的任务，在重试阶段优先发出，不再排在其它任务（可能正等几百毫秒响应）的重试之后；仍严格单在途、≥100 毫秒间隔、每条任务 20 次/15 秒窗口，不增加任何请求。
- 1.2.24 只把零点触发余量 `EARLY_GUARD_MS` 由 15 毫秒降为 10 毫秒（预计 wire 由 +22～26 提前到 +16～22 毫秒）；提前过多时仍由“不能预订超过2天的会议”规则按已确认未创建立即重试兜底，其他边界不变。
- 1.2.25 只加临近零点保护：放号前 5 分钟内拒绝“立即演练”（演练最长占用约 1 分钟，会拖晚零点提交）；控制页的检查登录/启用/核对在 60 秒内不覆盖误差更小的校时；本机墙钟锚点改为每次检查都刷新（原先只在启动后第一次检查时设置，长时间运行的漂移只会让首刀变晚）。不改触发公式、响应识别或任何提交边界。
- 严格校验响应形态、场馆规则和冲突文案；不凭 HTTP 200 或通用业务成功码重试。
- 日期上限过早提交、资源分配临时错误等只有被严格识别为“未创建”时才允许继续尝试。
- 不开发循环预约、自动签到、自动取消等能力；程序不会绕过场馆或平台的账号/时段规则。
- 测试通过不代表真实零点一定成功；平台并发、他人占用和网络状况都会影响结果。
- 使用前请确认场馆规则和平台条款允许此类辅助操作，风险自负。

## 技术栈

- Node.js ≥ 24
- TypeScript
- Playwright（驱动本机 Microsoft Edge，使用独立用户配置目录）
- 原生 `node:http` 本地服务 + 静态控制页
- `node:test` 单元测试

## 环境要求

- Windows 10/11
- Node.js 24 或更高版本
- 已安装 Microsoft Edge
- 能正常访问目标场馆预约网站的校园网/网络
- 具备预约权限的微信账号（需在专用 Edge 窗口中扫码登录）

## 快速开始

```powershell
npm install
npm run check
npm test
```

然后：

1. 双击 **`启动预约程序.cmd`**（账号1）。
2. 在弹出的专用 Edge 窗口中微信扫码登录。
3. 回到控制页，点击“检查登录”，确认账号和场馆规则已同步。
4. 新建任务：选择日期、时段、场地，建议先用 **dry-run（演练）** 验证表单，再启用正式任务。
5. 保持电脑开机、网络和专用 Edge 不关闭；零点由程序自动执行。
6. 在控制页查看结果；部分成功会保留已取得时段并停止。

需要第二个账号时：

- 运行 **`启动账号2.cmd`**，使用独立的 `38322` 端口和 `data-b/` 目录；
- 账号2 必须在同一场馆且已获授权；
- **不要在不同实例之间复制 `edge-profile`、`form-check.json` 或整个 `data-b/`**；
- 两个账号各自只能预约同一时间的一块场地，不能靠两个任务绕过平台“单账号同一时间只能一个会议”的限制。

## 配置

默认配置无需修改。需要自定义时使用环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BADMINTON_PORT` | `38321` | 本地控制页端口 |
| `BADMINTON_DATA_DIR` | `data` | 运行数据目录，必须是项目内以 `data` 开头的相对目录 |

数据目录限制为项目内的相对路径，且同一数据目录不能同时启动两个实例。

## 隐私与数据安全

- `data/`、`data-b/`、`edge-profile/` 包含登录资料、Cookie/令牌、任务和冻结状态，**已被 `.gitignore` 排除，禁止上传/提交**。
- 不要把 `data/`、`data-b/`、Edge 配置目录或包含二维码/登录信息的截图提交到 GitHub。
- 本机只读检查不要输出令牌、Cookie 或完整响应数据。
- 不要删除、重建或用旧副本覆盖 `data/`；需要迁移时请先备份并核对。
