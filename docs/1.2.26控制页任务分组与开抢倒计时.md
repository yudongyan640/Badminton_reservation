# 1.2.26 控制页：任务分组、开抢倒计时、账号标识

日期：2026-11-27

## 背景

界面审查（用演示数据渲染当前控制页）发现三个影响日常使用的问题：

1. 任务卡片按创建倒序平铺，`data/` 已有 76 条、`data-b/` 有 47 条任务，“等待执行”的那条容易埋在几十条历史里。所有已结束任务都是同一种灰色，成功、部分成功、未完成只能靠角落的小字区分。
2. 下次开抢时间只在卡片里以“开抢时间：2026/11/29 00:00:00”出现，没有倒计时，也没有“临近开抢别乱点”的提醒。
3. 账号1、账号2 两个窗口外观完全一样，只有页脚小字和标签页标题有端口号，并排时容易在错的窗口操作。

## 改动（仅 `public/app.js`、`public/index.html`、`public/style.css`）

### 任务分组

- **进行中**：等待执行、检查中、预约中、结果待确认。待确认排最前，其余按放号时间排序。没有任务时显示提示语。
- **待启用**：未启用、演练完成，按创建时间倒序。
- **历史记录**：完整成功、部分成功、未完成、已停止。按打球日期倒序，默认只显示最近 5 条，可点“显示全部 N 条历史记录”展开或收起。
  - 每条历史是一行：日期、时段、场地、正式/演练、状态。部分成功时附“实得 21:00–21:30”。
  - 点开一行显示原卡片的全部信息和操作按钮（未完成、已停止的任务仍可重新启用）。
  - 左边框按结果着色：成功绿、部分成功琥珀、未完成砖红。
- 页面每 1.5 秒轮询一次。只有任务数据、忙碌状态或展开状态变化时才重绘，展开的历史不会被收起；执行任何操作后都强制重绘一次，确保按钮可用状态正确。
- 结果提示（toast/声音）仍对全部任务生效，与分组无关。

### 顶栏开抢倒计时

- 取未暂停的等待任务中最早的放号时刻，显示“下次开抢 11-28 00:00 · 还有 03:25:19 · 1 条任务”，下面一行显示校时误差与最近检查时间。超过 24 小时时显示为“N 天 N 小时”。
- 距开抢 5 分钟内转为琥珀色，提示“临近开抢：请勿演练、刷新日历或关闭专用 Edge”（与 1.2.25 的后端限制一致）。
- 任务处于检查中或预约中时显示“正在预约 N 条任务…”。账号暂停且只剩正式任务时显示“账号已暂停：到点不会自动提交”。
- 倒计时只读页面已有的 `/api/state` 数据，按本机时钟每秒刷新，不新增接口，也不影响引擎的触发时刻。

### 账号标识

- 顶栏品牌旁显示“账号1 · 张三 · 38321”（`data` 目录为账号1，`data-b` 为账号2，其它显示目录名）。标签页标题前加“账号1/账号2”。
- 非 `data` 目录的实例（账号2）整页换用蓝色强调色，账号1 保持原来的绿色。

### 小屏

1000px 以下倒计时单独占一行；720px 以下隐藏“场边”文字，只留图标与账号标签，历史行改为两行。无横向溢出。

## 不改动

后端代码（`src/`）、接口、零点链路、响应识别和所有提交边界；任务卡片里的信息和按钮语义；月历。

## 验证

- `tsc --noEmit` 通过；`node --test --test-isolation=none --test-concurrency=1 "tests/*.test.ts"` 135 项全部通过（本版没有改后端）。
- 用临时演示服务器验证：真实 `createApp`，假站点对象，临时数据目录，不启动调度、不打开 Edge、不访问场馆网站。分别在 1440×1000 与 375×812 下检查了账号1（绿）和账号2（蓝、5 分钟内琥珀倒计时）。具体验证：
  - 历史折叠与展开；展开后跨多次轮询保持展开；
  - 小屏无横向溢出；
  - “保存任务 → 立即演练 → 演练完成”流程、结果提示和按钮恢复；
  - 无控制台错误。
- **未运行** `npm run smoke` 与 `npm run smoke:calendar`：本环境没有 Edge，也没有 Playwright 浏览器。两个脚本依赖的选择器与按钮名（`.task`、`data-status`、“保存任务”“立即演练”“检查登录”“刷新预约”“下个月”）都保留了，历史行仍是 `.task` 元素。请在 Windows 本机补跑。

## 生效

控制页文件每次打开页面时从磁盘读取，**刷新浏览器页面即生效，不需要重启实例**；后端未改动。真实零点行为不受影响。
