# 1.2.16 扫码登录误判修复

2026-11-10 现场只读诊断：账号1实例（38321、data）无活跃任务及冻结；专用 Edge 只有一个场馆页面，loginUser.id 存在，window.sessionId 为空字符串。普通 Cookie 查询和带当前网页原请求头的 settings 查询均返回 HTTP200、code=0、success=true 及有效场馆设置。

根因：BrowserSite.ready 同时要求 sessionId 和 loginUser.id 非空；BrowserSite.api 又在 sessionId 为空时本机返回401。两处均会在请求网站前拒绝合法的 Cookie 会话。

修复：页面就绪要求 loginUser.id 存在，请求前亦要求账号存在；空 sessionId 原样随原请求头发送，继续使用 credentials=same-origin。是否接受会话由网站响应决定，网站401/403仍拒绝。保留来源限制、发送前账号匹配、GET后账号复核、表单证明、冲突响应匹配、重试边界和未知结果暂停逻辑。

验证：新增2项单元测试先在旧代码失败，修复后完整121项测试及 npm run check 通过。npm run smoke 新增空 sessionId 预检、日历读取、网站401仍拒绝和模拟提交请求头校验；两个 smoke 均通过，演练拦截4次、实际写转发0、pageErrors为空。全部自动化均使用隔离的本地夹具，无真实创建或取消预约。
