# 1.2.22 诊断留痕（首刀与首轮冲突）

## 背景

2026-11-23 00:00（放号 11-23，账号2）目标 11-23 20:00–21:00 的任务 `64bdd7c4-23bd-4fd5-b6bb-a419aba228f6` 以场2 为首选，但最终落在场1。复盘时发现两处信息被覆盖、无法回答“为什么没拿到场2”：

- `Task.triggerDelayMs`、`wireTriggerDelayMs`、`responseMs` 永远指向**最近一次**尝试。该任务 3 次尝试，字段显示的是第 3 次的 +1314 毫秒，首刀到底几点发出已不可知；同批 21:00 任务只有 1 次尝试（+467 毫秒），才留下首刀时间。
- 首轮冲突的冲突区间、被掩掉的场地、本地改投目标只存在内存中的 `conflictHints`，零点一过 `conflict-local-reselect` 之前的现场无法从 `events.ndjson` 还原。

结果是：看到“冲突→改投成功”时，无法区分“首刀本来就没抢到”与“首刀晚了、改投又晚了一步”。

## 改动（只加记录，不改行为）

- `src/domain.ts`：`Task` 新增
  - `firstShot?:{at:number;roomId:string;start:string;end:string;triggerDelayMs:number;wireTriggerDelayMs?:number;responseMs?:number;kind?:string}`——首次提交写入一次，之后重试只更新“最近一次”的字段，不覆盖它；
  - `lastConflict?:{at:number;roomId:string;begin?:string;end?:string;reselectRoomId?:string;reselectStart?:string;reselectEnd?:string}`——首轮冲突的现场与本地改投结果。
- `src/store.ts`：`event(t,event,detail?)` 增加可选 `detail`，事件行只多一个 `detail` 字段，既有字段不变。
- `src/engine.ts`：
  - `submitAttempt` 在 `t.attempts===1` 时写 `firstShot`（`at`/`roomId`/`start`/`end`/`triggerDelayMs`），响应回来后补 `responseMs`/`wireTriggerDelayMs`/`kind`（只补一次）；
  - `processResult` 在首轮冲突（`conflictsSinceRefresh<1`）本地重选后写 `lastConflict`，并落 `conflict-local-reselect` 事件，`detail` 含 `roomId`/`conflictStart`/`conflictEnd`/`reselectRoomId`/`reselectStart`/`reselectEnd`（无区间或无候选时对应值为 `null`）。
- 版本号 `package.json` 1.2.21 → 1.2.22。

## 不改动

提交与重试节奏、100 毫秒全局下限、单在途、每条任务 20 次/15 秒、首波并发（1.2.21）、零点刷新限时 150 毫秒、`DEGRADED_LIST_TIMEOUT_MS=300`、`ZERO_RECHECK_TIMEOUT_MS=1500`、冻结与核对逻辑、严格响应/冲突形态校验均不变；不增加任何网络请求。

## 测试

`npm run check` 通过；`node --test --test-isolation=none --test-concurrency=1 "tests/*.test.ts"` 130 项全部通过。新增 2 项：

1. transient 后重试成功：`firstShot.triggerDelayMs` 仍为首刀的 20 毫秒、`firstShot.kind` 仍为 `transient`，最近一次尝试的 `triggerDelayMs` 单独为 120 毫秒（含 100 毫秒全局下限）；
2. 首轮冲突：任务 `lastConflict` 记录冲突场地/区间（场1、22:00–22:30）与改投目标（场2、22:00–23:00），`conflict-local-reselect` 事件的 `detail` 与之一致。

测试使用 FakeSite，无真实创建/取消，实际预约写转发 0。

## 风险与未验证

- 真实零点尚未产生带新字段的运行记录；这些字段只增不改，旧 `tasks.json` 加载时保持原样（`validateTask` 只用于导入新任务）。
- 字段变大使 `tasks.json` 略大，但不影响原子落盘与读取。
- `npm test` 在本机沙箱仍报 `spawn EPERM`，用 `--test-isolation=none` 同进程运行规避。
- 两个实例需重启后才加载新代码；`data`/`data-b` 无需迁移。

## 生效

重启两个实例并在专用 Edge 重新“检查登录”。下一次零点后：

- `tasks.json` 的每条正式任务应带 `firstShot`，发生过冲突的应带 `lastConflict`；
- `events.ndjson` 首轮冲突应出现 `conflict-local-reselect` 且带 `detail`。
